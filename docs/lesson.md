# Практикум JMeter

Цель занятия — измерить пропускную способность и задержку учебного Flask и связать результаты клиента с графиками сервера.

## 1. Проверьте стенд

[Запустите стенд](../README.md#быстрый-запуск) и выполните JMeter smoke из корня репозитория.

```sh
docker compose run --rm --build jmeter smoke
```

План [smoke.jmx](../jmeter/smoke.jmx) посылает по одному запросу на `/health`, `/api/fast`, `/api/slow` и `/api/flaky`. Для проверки нестабильного маршрута вероятность ошибки установлена в ноль. Все четыре запроса должны вернуть HTTP 200. Откройте HTML-отчёт по пути из терминала.

## 2. Сравните базовый сценарий, задержку и ошибки

По очереди запустите [load.jmx](../jmeter/load.jmx) с теми же числом пользователей и длительностью. В Docker запросы идут к Flask внутри сети Compose. Для изучения маршрутов откройте [приложение](http://127.0.0.1:5000/).

```sh
docker compose run --rm jmeter load -JUSERS=10 -JDURATION=30
docker compose run --rm jmeter load -JUSERS=10 -JDURATION=30 "-JPATH=/api/slow?delay_ms=250"
docker compose run --rm jmeter load -JUSERS=10 -JDURATION=30 "-JPATH=/api/flaky?error_rate=0.15"
```

В каждом прогоне дайте тесту завершиться и запишите показатели. В последнем сценарии часть запросов намеренно получает HTTP 503. Фактическая доля зависит от выборки.

| Сценарий | RPS JMeter | p95 JMeter, мс | Ошибки в JMeter, % | Графики RPS, p95 и 5xx в Grafana |
| --- | ---: | ---: | ---: | --- |
| Быстрый | | | | |
| Задержка 250 мс | | | | |
| Ошибки с вероятностью 15% | | | | |

Откройте [дашборд Flask](http://127.0.0.1:3000/d/flask-load-lab). Выберите период, охватывающий ваши запуски. Ответьте на вопросы:

1. Как изменились p95 и RPS после добавления задержки при том же числе пользователей?
2. Какой маршрут поднял долю 5xx? Что покажет общее число ответов в секунду, если часть ответов ошибочна?
3. Что входит во время ответа JMeter и почему оно может отличаться от задержки в Grafana?

## Запуск в графическом интерфейсе JMeter

Для этого варианта установите Apache JMeter 5.6.3 и Java 17. Откройте `jmeter/smoke.jmx`, запустите один короткий тест и проверьте запросы в **View Results Tree**. Адрес по умолчанию — `127.0.0.1:5000`. Для измерений используйте запуск без GUI.

Чтобы выполнить нагрузочный план с локальным JMeter, из корня проекта запустите следующую команду. В Windows замените `jmeter` на `jmeter.bat`. Указывайте новое имя JTL и новый каталог HTML при каждом запуске.

```sh
jmeter -n -t jmeter/load.jmx -JUSERS=10 -JDURATION=30 "-JPATH=/api/slow?delay_ms=250" -l reports/local-slow.jtl -j reports/local-slow.log -e -o reports/local-slow-html
```
