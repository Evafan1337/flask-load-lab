# Памятка преподавателю

## Подготовка до урока

1. Выполните `scripts/Start-Lab.ps1`, проверьте Flask, Grafana, Locust и страницу Prometheus `/targets`.
2. Откройте два дашборда Grafana рядом с Locust. Установите одинаковый временной диапазон. Для коротких запусков удобны последние 15 минут.
3. Проведите baseline 10 пользователей на 60 секунд. Убедитесь, что метрики появились. После остановки оставьте графики и объясните, что история остаётся в Prometheus.
4. Покажите ученику каталог `reports/`: автоматические прогоны сохраняют CSV и HTML. Сравнивайте интервалы одинаковой длительности и не включайте разгон в одну серию, если убрали его из другой.
5. На занятии используйте один активный генератор: либо браузерный тест, либо `Run-LoadTest.ps1`. Два одновременных запуска создадут общую нагрузку на Flask, а пользовательская статистика будет разделена между генераторами.

## План на час

| Время | Действие | Контрольный вопрос |
|---|---|---|
| 0–5 мин | Схема стенда, проверка UP | Кто создаёт нагрузку, кто собирает метрики? |
| 5–13 мин | baseline | Чем пользователи отличаются от RPS? |
| 13–23 мин | slow | Может ли сервер быть медленным при свободном CPU? |
| 23–31 мин | errors | Может ли быстрый ответ быть плохим? |
| 31–39 мин | cpu | Как проверить гипотезу о вычислительном ограничении? |
| 39–49 мин | mixed | Почему общий p95 не заменяет разбиение по маршрутам? |
| 49–60 мин | Таблица, выводы, остановка | Какая метрика подтверждает каждый вывод? |

## Ожидаемые признаки

| Профиль | Что меняется по замыслу | Чего не нужно обещать |
|---|---|---|
| baseline | Только быстрый маршрут | Конкретный универсальный RPS |
| slow | Время ответа растёт минимум на заданную задержку при отсутствии очереди | Обязательный высокий CPU |
| errors | Около 15% HTTP 503 на длинной серии | Ровно 15% на малой выборке |
| cpu | Вычисления на каждый запрос | Насыщение CPU на любом компьютере при 10 пользователях |
| mixed | Видны разные классы маршрутов | Точное соотношение 8:2:1:1 в каждой секунде |

Для автоматического запуска используйте параметры скрипта `-DelayMs`, `-ErrorRate`, `-CpuIterations`. Например:

```powershell
.\scripts\Run-LoadTest.ps1 -Scenario slow -Users 10 -Duration 60s -DelayMs 500
.\scripts\Run-LoadTest.ps1 -Scenario errors -Users 10 -Duration 60s -ErrorRate 0.01
.\scripts\Run-LoadTest.ps1 -Scenario cpu -Users 10 -Duration 60s -CpuIterations 500000
```

Обёртка принимает 1–100 пользователей, длительность `10s`–`5m`, задержку 0–2000 мс, вероятность 0–1 и 1000–1000000 итераций. Для прямого запуска Locust аналогичные настройки задаются через `LAB_DELAY_MS`, `LAB_ERROR_RATE`, `LAB_CPU_ITERATIONS` перед созданием процесса. Значения по умолчанию: 250 мс, 0.15 и 100000 итераций. Сценарий можно выбирать в Web UI перед каждым запуском через `lab-scenario`, не перезапуская Locust. Изменение этих переменных в другом PowerShell не изменит уже работающий процесс.

## Разбор типичных затруднений

**Пустой график сразу после старта.** Проверьте UP, временной диапазон и выбранный job. Дождитесь нескольких сборов. Для Flask используйте учебный дашборд, для пользователей — Locust. Native UI имеет job `locust`, отдельный запуск скриптом — `locust_headless`.

**В Locust есть ответы, а приложение не видно на графике.** Проверьте host; учебный адрес — `http://127.0.0.1:5000` на Windows и `http://flask:5000` между контейнерами. Проверьте `http://localhost:5000/metrics`. Временные запросы `/health` и `/metrics` исключены из нагрузки на основных панелях.

**Счётчик обнулился после нового теста.** Это ожидаемо для Locust. Используйте `rate(counter[...])` для скорости. Сырые накопительные значения нельзя сравнивать между разными запусками без учёта сброса.

**p95 Locust и Flask не совпадают.** У них различаются границы измерения, окна и способ вычисления. В Flask это оценка по bucket-гистограмме на выбранном интервале; в Locust — перцентиль текущего теста с округлением длительности. Сравнивайте тенденцию и порядок величины, затем уточняйте период.

**HTTP 503 и код завершения теста.** При прямом запуске Locust ошибки по умолчанию дают ненулевой код. Учебная обёртка `Run-LoadTest.ps1` и стандартный Docker-профиль сохраняют ошибки в статистику, но не применяют пороги успешности: намеренные 503 не прерывают демонстрацию. Проверяйте `failures` в `run.json`, CSV и раздел ошибок HTML-отчёта, даже если команда завершилась без ошибки. Тайм-ауты и ошибки соединения также попадают в число failures и требуют отдельного разбора; в `baseline` они не ожидаются.

**CPU и память процесса не отображаются.** Проверьте на `/metrics` наличие `flask_process_cpu_seconds_total` и `flask_process_resident_memory_bytes`. В этом проекте `psutil` обеспечивает сбор и в Windows, и в Linux. Для CPU нужен интервал с несколькими точками, поскольку график использует `rate()` накопленного процессорного времени.

## Дополнительные задания

- Сравнить 5, 10 и 20 пользователей, удерживая сценарий и длительность постоянными.
- Подобрать задержку и описать её влияние на RPS при фиксированном числе пользователей.
- Уменьшить вероятность ошибки с 15% до 1% и объяснить, почему нужен более длинный тест.
- Написать простой критерий: например, «в этом учебном эксперименте p95 < 500 мс, доля ошибок < 1%». Уточнить профиль, длительность, пользователей и допустимость прогрева. Эти числа — выбранное учебное условие, а не общее требование к Flask.
- Добавить новый маршрут и убедиться, что метки метрик используют шаблон маршрута, а не идентификаторы объектов или query string.

## Границы модели

В одном процессе Waitress использует потоки. Задержки `sleep` освобождают процессор, а Python-вычисления конкурируют за него и интерпретатор. Здесь нет БД, внешней сети, распределённого генератора или модели production-трафика. Locust применяет закрытую модель: каждый пользователь ждёт завершения своего запроса и паузу; это не генератор фиксированной интенсивности запросов.

Не увеличивайте нагрузку на порядок без цели: на одном компьютере генератор и Grafana также расходуют CPU. Для занятия достаточно 5–20 пользователей. При прямом запуске Locust для других серверов предусмотрен явный `LAB_ALLOW_REMOTE=1`; используйте его только для своих согласованных целей. По умолчанию генератор принимает локальные host и контейнерный `flask`, а Windows-обёртка всегда направляет нагрузку на `127.0.0.1:5000`.
